# Wildcard 嵌套与顺序批量

[English](wildcard-nesting.md)

Prompt Scheduler 在**顺序**模式下，按「叶子空间」计数并展开，而不是各层共用一个 `index % 数量`。本文说明规则、常见组合与注意点。

相关入口：节点 **Prompt Scheduler** → 栏目模式选「顺序」→「统计数量」/「批量运行」。

---

## 规则一览

| 场景 | 行为 |
|------|------|
| 一个 `__key__` 下多个候选（文件夹多文件、TXT 多行、多张 JSON） | **求和**：从左到右耗完一支再进下一支 |
| 候选正文里再写 `__…__` | **递归**进内层，继续按上表计算 |
| 同一栏位文本里并排多个 `__a__, __b__` | **求积**（左外、右内） |
| 多个顺序栏目 | **各自**算叶子长度，任务数取 **max**；短栏循环，栏与栏不做积 |
| `{a\|b}`、权重、`$$` 多选、`N#__key__` | **始终随机**，不拉长顺序周期 |
| 随机 / 洗牌栏目 | 在整段叶子空间上抽 / 洗牌（`{}` 仍始终随机） |

「统计数量」与真实顺序展开使用同一套叶子空间；`{}` 内的 `__key__` **不计入**顺序任务数。

---

## 语法从哪来

Impact 风格，本插件内置解析：

- `__文件夹__` / `__路径/文件__`：引用库中的文件夹或单文件  
- TXT：一个文件多行 = 多个候选；某行可以是纯文本，也可以再写 `__…__`  
- JSON 卡片：`content`（及 `negative`）里可以再写 `__…__`，展开时带上该卡的 LoRA / 负面 / 稀疏生成设置  
- `{a|b}`、`{2::a|1::b}`、`{2$$, $$a|b|c}`、`3#__key__`：选择/多选类，批量时按随机处理  

TXT 与 JSON 可以互相嵌套（JSON 正文引用 TXT 词库，或反过来）。

## 例子（建议自己对照「统计数量」）

下列用抽象叶子名；库结构请自行建文件夹/文件，或对照本地测试包思路。

### 1. 同栏并排 = 积

栏目文本：

```text
__pool/a__, __pool/b__
```

若 `a` → `a1,a2,a3`，`b` → `b1,b2`：

- 统计：**6**
- 顺序：

```text
a1, b1 → a1, b2 → a2, b1 → a2, b2 → a3, b1 → a3, b2
```

### 2. 嵌套树 = 分支求和

`pack` 下两张卡/两行：

1. 内容 `__pool/inner__`（`i1,i2`）  
2. 内容 `plain`

栏目：`__pool/pack__`

- 统计：**3**
- 顺序：`i1 → i2 → plain`

### 3. 套件：多分支词库

`suite` → 分别指向 `__pool/x__`（3 叶）与 `__pool/y__`（2 叶）：

- 统计：**5**
- 顺序：先耗完 x，再 y  

适合「普通场景 / 角色场景」分支配方。

### 4. 外层多卡 × 内层积

两张外层卡，每张 `content` 都是 `__pool/a__, __pool/b__`（积为 6）：

栏目：`__pool/outer__`

- 统计：**12**（2×6）
- 顺序：先完整 6 步，再对第二张卡重复 6 步  

典型用法：外层换 LoRA/预设，内层扫场景×姿势。

### 5. 树 × 积（写在同一正文）

一张卡内容：`__pool/pack__, __pool/b__`（pack 为 3 叶，b 为 2 叶）：

- 统计：**6**
- 顺序：`i1,b1 → i1,b2 → i2,b1 → i2,b2 → plain,b1 → plain,b2`

### 6. TXT 多行，每行一个通配符

`menu.txt`：

```text
__pool/a__
__pool/b__
__pool/pack__
```

栏目：`__pool/menu__`（或该文件的路径 key）

- 统计：各行叶子之和（如 3+2+3=**8**）
- 顺序：先扫完 a，再 b，再 pack  

这是「目录式入口」的简易写法；某一行也可以写成 `__a__, __b__`（该行按积计入总和）。

### 7. JSON 嵌套（与 TXT 同规则）

JSON 只是候选载体：多张卡 = 多分支；`content` 里写 `__…__` 即嵌套。  
跨格式示例：JSON 的 `content` 为 `__某TXT词库__`，顺序统计同样按展开后的叶子算。

### 8. `{__a__|__b__}`（不要当成顺序并集）

```text
{__pool/a__|__pool/b__}
```

- 每次：**随机**选 a 或 b，再在该侧**随机**抽  
- 统计：**0**（不占顺序周期）  
- 若要 `a1→…→a3→b1→b2` 的顺序并集，用第 6 节多行 TXT / 多卡文件夹，不要用 `{}`

### 9. 同栏 `{红|蓝}, __pool/a__`

- 统计：只算 `a`（如 **3**）  
- `a` 顺序推进；颜色每轮随机  

### 10. 多栏目

- 栏 1：`__pool/a__`（3）  
- 栏 2：`__pool/b__`（2）  
- 统计：**3**（max）  
- 第 3 张时栏 2 回到 `b1`；两栏**不会**做成 3×2 积

## 实用配方

**对比 LoRA / 预设 × 共享场景**

1. 文件夹 `lora测试/`：每张 JSON 绑不同 LoRA，`content` 里写 `__场景__` 或 `__套件__`  
2. `套件/` 再分「普通 / 角色」等分支，分支内继续嵌套  
3. Scheduler 一栏顺序：`__lora测试__`，点统计 → 批量  

**词库分层**

- 顶层：风格 / 角色入口（JSON，方便挂 LoRA）  
- 中层：套件 TXT 或多卡目录  
- 底层：具体 tag 行  

**纯随机调味**

- 固定顺序轴用 `__…__`  
- 不影响周期的变化用 `{a|b}` 或权重写法

## 注意点

1. **统计与展开一致**：改库后先刷新提示词库；改过 Python 逻辑需重启 ComfyUI。  
2. **`{}` / `N#` 不进顺序计数**：只有花括号时统计为 0，属预期。  
3. **随机按叶子均匀**：大分支叶子多则更容易抽到；若需要「先 50/50 选文件夹」，用 `{__大__|__小__}`（始终随机选分支）。  
4. **同栏写两个相同 key**（`__b__, __b__`）会做积，提示词里很少需要。  
5. **JSON `content` 换行 ≠ TXT 多行**：JSON 一整段仍是一个候选；要多分支请用多张卡或 TXT 多行。  
6. **负面栏 / 固定负面**里同样可写通配符，规则与正面相同。
